# 창 최소화 지연 점검 (2026-11-25)

사용자 보고: 창 최소화(노란 버튼)가 닫히기까지 약 20초 걸리고 애니메이션이 제대로 보이지 않는다. 복원은 약 2초. kext 0.0.42.

## 방법

- 사용자가 노란 버튼으로 Finder 창, Claude 창 순서로 최소화하고 Dock에서 다시 연다. 그동안 `top -s 1`로 WindowServer·Dock CPU를 1초마다 기록한다(150초).
- Claude 앱이 이 VM 안에서 돌기 때문에, Claude가 작업하는 동안에는 WindowServer가 계속 약 160%(HiDPI)를 쓴다. 측정은 Claude가 쉬는 동안(백그라운드 기록, 대화 차례 종료 뒤)에 했다.
- AppleScript(`set collapsed of front window`)로 최소화하면 Genie 애니메이션 부하가 나타나지 않아(최대 49%, 2초 안에 0%) 측정에 쓰지 않았다.

## 결과 (vCPU 4개)

| 조건 | Finder 최소화 (체감) | Claude 창 최소화 (체감) | 최소화 중 WindowServer |
| ---- | -------------------- | ----------------------- | ---------------------- |
| 우리 드라이버, 2560×1600 HiDPI | 3초 | 7초 | 190~271%, 8~10초 |
| 우리 드라이버, 1280×800 1:1 | 2초 | 3초 | 163~236%, 1~2초 |
| IONDRV(`-vvideooff`), 1280×800 | 1.5초 | 2초 | 107~233%, 1~3초 |

- 드라이버의 화면 전송은 측정 내내 초당 약 52회로 평소와 같았다.
- Claude가 작업 중일 때(WindowServer가 이미 약 160%)는 같은 최소화가 더 오래 걸린다. 처음 보고된 20초는 이 경우로 본다(시각을 맞춰 확인하지는 못함).

## 결론

- 같은 1280×800에서 우리 드라이버와 IONDRV의 최소화 시간·부하는 비슷하다. 드라이버 고유의 문제로 보지 않는다.
- HiDPI에서 느린 것은 Metal이 없어 WindowServer가 4배 많은 픽셀(2560×1600)의 Genie 애니메이션을 CPU로 그리기 때문으로 본다. IONDRV는 HiDPI 모드가 없어 HiDPI끼리는 비교할 수 없다.
- 코드는 바꾸지 않았다. 알려진 제약으로 INSTALL.md §8에 적었다.
- 우회: 1280×800 1:1 모드를 쓰거나, Dock의 최소화 효과를 "크기 조절"로 바꾼다(`defaults write com.apple.dock mineffect -string scale; killall Dock`, 시험하지 않음).
