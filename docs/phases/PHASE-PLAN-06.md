## 1. 목표

핵심 목표 밖의 편의 기능이다. M3 이후 필요하다고 판단될 때만 시작한다. 시작 전에 이 문서를 실측 결과(WI-3.005 이벤트 동작 등)로 갱신한다.

## 2. Work Item 상세

### WI-6.001 창 크기에 맞춘 자동 해상도 전환 (1.5)

- 선행 조건: WI-3.005에서 GTK 창 크기 변경 시 `VIRTIO_GPU_EVENT_DISPLAY`가 온다는 것이 확인되어야 한다. 오지 않으면 이 WI는 취소로 표시한다 (삭제하지 않음).
- 이벤트 → 새 선호 크기를 동적 모드로 추가 → 설정이 켜져 있으면 그 모드로 전환(WI-3.002 경로).
- 연속 리사이즈 중 전환이 몰리지 않게 마지막 이벤트 후 일정 시간(상수) 기다렸다가 전환한다.
- 수락 기준: 창 크기를 바꾸면 게스트 해상도가 따라 바뀌는 녹화, 설정으로 끌 수 있음.

### WI-6.002 다중 scanout (3)

- 사용자가 호스트에 `max_outputs=2`를 지정한다 (HST-003).
- scanout마다 `IOFramebuffer` 인스턴스, resource, 메모리 풀 몫을 나눈다. 풀 128 MiB 안에서 배분 규칙을 정한다.
- 수락 기준: 시스템 설정 > 디스플레이에 모니터 2개, 배치 변경, 각각 출력되는 스크린샷.

> 계획 단계의 스케치다. 시작 시점의 실측이 우선한다.

## 결정 기록

### WI-6.001 창 크기 자동 전환 (2026-11-25, kext 0.0.48)

- 선행 조건: 일반 virtio-vga + GTK에서 사용자가 창 크기를 바꾸면 `VIRTIO_GPU_EVENT_DISPLAY`가 온다(870×528, 1729×956 실측). 게스트가 모드를 바꿀 때도 QEMU가 창을 그 크기로 맞추고 같은 크기로 이벤트를 보낸다. WI-1.005의 "이벤트 없음"은 창 크기를 바꾸지 않은 경우였다.
- 구조: 드라이버가 창 크기를 동적 모드로 넣고 IOGraphics에 연결 변경을 알린다(`registerForInterruptType(kIOFBConnectInterruptType)` 콜백, 이벤트가 600 ms 멎은 뒤). 사용자 공간 에이전트 `vvresize`(LaunchAgent)가 마무리한다. 사용자 승인("에이전트로 진행").
- 실측으로 정한 것:
  - 모드 목록만 바꾸면 macOS가 다시 읽지 않는다. 연결 변경 통지가 필요하다(0.0.42: CG 목록 10개 그대로).
  - 프레임버퍼의 `getWorkLoop()`는 start 때 null이었다. 타이머는 GPU 서비스 워크루프에 붙인다(0.0.43).
  - WindowServer는 연결 변경 뒤 저장된 모드로 돌아갈 뿐 새 모드로 바꾸지 않는다. 에이전트가 필요하다(0.0.44). `CGDisplayRegisterReconfigurationCallback`은 이때 오지 않아 1초 주기로 상태 속성을 읽는다.
  - 연결 변경 뒤 WindowServer는 EDID 선호 타이밍(= QEMU 창 크기)과 같은 모드로 먼저 간다. 너비를 8의 배수로 내리면(1192 대 1194) 맞는 모드가 없어 2560×1600으로 갔다. 창 크기를 그대로 쓴다(홀수 너비도 정상 표시 확인, 0.0.46).
  - WindowServer는 저장된 **모드 ID**로 돌아간다. 동적 ID를 100/101로 번갈아 쓰면 직전 크기로 한 번 돌아가 깜박임이 2번이었다. ID 100 하나만 쓰고 크기만 바꾸며, 에이전트는 바꾼 모드를 설정에 저장한다(`.permanently`). 그 뒤 창 크기 변경당 깜박임 1번, 에이전트 개입 없음(0.0.47).
- 0.0.45~0.0.47의 진단 기록(현재 모드 조회 등 자주 불리는 함수에서 IORegistry 속성 쓰기)이 있을 때 종료 중 화면이 멈췄다(0.0.45 Nested panic 보고서, 0.0.46 사용자 확인). 진단 기록을 뺀 0.0.48은 창 크기를 바꾼 뒤에도 정상 재부팅됐다. 이 VM의 ShutdownCause는 정상 재부팅도 대부분 3(전원 버튼)으로 남아 판단 근거로 쓸 수 없다.
- 끄기: `VVAutoResize`(Info.plist, 기본 1), boot-arg `vvideo_autoresize`. 끈 상태에서는 현재 동적 모드를 쓰는 동안 목록을 바꾸지 않고 연결 변경도 알리지 않는다(실측).
- 수락 기준의 녹화는 하지 않았다(게스트 녹화 불가). 사용자 육안 확인과 드라이버 로그로 판정했다.
- 남은 것: 저장된 모드가 표준 모드일 때는 깜박임 2번(WindowServer 복원 → 에이전트). HiDPI 배율 모드를 쓰는 중에 창 크기를 바꿀 때의 동작은 확인하지 않았다(에이전트는 1:1 모드를 고른다).

### WI-6.002 다중 scanout — 보류 (2026-11-25)

- 호스트: `-device virtio-vga-gl,max_outputs=2`. 장치가 scanout 2개를 알린다. 1번은 호스트 GTK에서 그 탭(`virtio-vga-gl.1`)을 열 때 `enabled=1`이 되고 디스플레이 이벤트가 온다. 열기 전에는 0×0(off), 호스트 창에는 "Display output is not active".
- 시험 구현(0.0.49~0.0.50, 커밋 안 함): 128 MiB 풀을 출력마다 64 MiB로 나누고, 켜진 추가 출력마다 `VirtioVideoOutput` nub을 만들어 같은 `VirtioVideoFramebuffer` 클래스를 하나 더 붙였다. 추가 출력은 자기 resource·전송 루프(전체 전송), 출력별 EDID, 커서는 보이는 출력의 scanout으로 보냈다.
- 실측:
  - 부팅 때 1번이 이미 켜져 있으면 두 화면 모두 그려졌다(`system_profiler` 모니터 2개, 출력 1 전송 오류 0). 다만 1번 프레임버퍼가 먼저 붙어 macOS가 주 디스플레이로 골랐다(0.0.50에서 순서를 고쳤으나 설치하지 못함).
  - 부팅 뒤 탭을 열어 새로 붙은 프레임버퍼에는 IOGraphics가 아무것도 묻지 않았다(호출 기록 `start start-done`뿐, `enableController` 없음). 실행 중 새 IOFramebuffer는 WindowServer가 열지 않는 것으로 보인다.
  - 두 출력 상태에서 키보드 입력이 되지 않았고, 사과 메뉴 재시작 중 두 화면이 검게 멈췄으며, GTK "Detach Tab" 때 화면이 꺼졌다. 원인은 확인하지 못했다.
- 결정: 사용자 결정으로 보류하고 0.0.48로 되돌렸다. 시험 코드는 `git stash`("WI-6.002 multi-output WIP")에 보관했다. 호스트 `max_outputs`는 1로 되돌리는 것을 권한다.
- 다시 시작한다면: 장치가 알린 scanout마다 부팅 때 프레임버퍼를 모두 만들고, 꺼진 출력은 연결 끊김(`kConnectionCheckEnable`)으로 보고하다가 켜질 때 연결 변경을 알리는 구조로 바꾼다. 키보드·재시작 멈춤은 따로 조사한다.
